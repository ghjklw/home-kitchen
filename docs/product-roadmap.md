# Home Kitchen product roadmap

Updated 2026-11-16. This is the single backlog for product features, integrations, UX work, bugs, and operational readiness. It reflects the product owner's requests and implementation evidence available on this date; code presence alone does not count as a verified outcome.

## How to maintain this roadmap

- The product owner owns priorities, product direction, and acceptance decisions at a high level. All implementation work is delegated to Luna, who updates status and adds concise validation evidence when work changes.
- Record user ideas before implementation. Keep unresolved items visible; do not delete them when priorities change. Update an existing stable ID instead of creating a competing plan.
- `Implemented` means verified locally through the API or UI only. It does not mean the whole user journey is accepted, deployed, or production-ready. `In progress` means partial work exists or is being validated. `Blocked externally` means a provider, platform, or external decision currently prevents completion. `Requested` means not yet verified as implemented. Use `Accepted` only after the item's criteria and relevant connected journey are verified; this still does not imply production deployment.
- Priorities: `Now` completes the next coherent end-to-end release slice; `Next` follows that slice; `Later` is valuable but not on the immediate path. Priorities can change without changing IDs.
- Each acceptance statement is observable. A feature is accepted only when its stated behavior and the connected journey gates below have been checked.

## Current focus

Complete and validate one household journey: find or add a source recipe → adapt and explicitly save it → plan it without overwriting meals → review a useful shopping list and exact products → cook from consistent scaled quantities → record actual purchases and feedback. The shopping match UI is in progress. Bulk importing Oda recipe collections, recipe-photo workflows, shared-list refresh, and consumer MCP authentication are also incomplete. Existing API checks do not establish a complete PWA, phone-client, UAT, or production journey.

Delivery order: (1) automatic, compact shopping and correct quantities; (2) connection management and aisle order in Settings; (3) source acquisition through bulk Oda import, photo transcription and image selection; (4) catalogue/preferences, purchase completion and shared-device handoffs; (5) validated Cookidoo/TM6 planning and consumer assistant connections. Work may run independently, but backend-only work does not close a UI item.

## Evidence and release gate

Evidence captured for this roadmap on 2026-11-15: local service at `localhost:18085` was running backend revision `fc7c558` with schema migration `0013`; a later root type fix was not present in that running process. Live Oda connection and multi-query product search worked. An AI-adapted recipe draft returned HTTP 200 and required review while the saved recipe stayed unchanged. Shopping match jobs started in about 0.31 seconds, completed four needs in about four seconds, and returned the same job on repeat in about 0.02 seconds. Examples included 1000 ml milk mapped to one 1.75 l pack and 233 g pasta to one 500 g pack. These are local observations, not general provider guarantees.

Shopping UI follow-up on the same retained runtime showed compact automatic suggestions for all four needs, with a primary result and four collapsed alternatives per item; known quantities mapped Milk (1000 ml) to one 1.75 l pack and Pasta (233.33 g net) to one 500 g pack. Same-period Needs ↔ Oda navigation reused ready results. Returning to Dec 7–13 after visiting Nov 30–Dec 6 still showed a search in progress after more than 10 seconds, so period restoration is unverified rather than a proven infinite hang. Coffee, Milk, Tomato, and all expanded Milk alternatives showed unavailable images; Pasta showed a photo. Follow-up against a current public Oda milk page verified the escaped `&amp;` query as the cause: its raw CDN URL returned 403, while the HTML-unescaped URL returned 200 `image/jpeg`. A source fix and regression test are implemented, with 63 focused tests passing; retest in the Kitchen UI is pending, and individual-item photo acceptance remains open because Coffee, Tomato, and all Milk alternatives have not been live-verified. The Coffee need's primary suggestion was Nestlé Coffee mate, so S-003 remains open. User selection/cart writes and the known-quantity chooser flow remain unverified.

Additional verified UI/API slices: planned cooking displayed two servings while the saved recipe remained at three; source discovery returned real Oda and Marmiton results, with Matprat keyword discovery unsupported but URL import available; multi-day meal planning, conflict handling, manual recipe entry, editing, and removal of from-scratch AI were UI-verified. Oda's read-only liked/purchased recipe tools were verified with one-row samples; their limits are 50 pages of 20 and URLs may be null. Catalogue seeding and API currently expose 37 foods; catalogue consumers and household category-order editing still need UI work. Finish-purchase API behavior is implemented but its UI is pending. Local MCP protocol/catalogue checks do not verify external Claude or Gemini sign-in. Photo helper tests pass, but photo API/UI integration and photo search remain in progress.

Before calling a household journey accepted, verify it in the intended PWA/client with real, current provider responses where applicable: source discovery/import and attribution; review/edit/save without losing an existing recipe; plan confirmation with conflicts; consistent cooking and shopping quantities; fresh product/availability review; explicit purchase completion; and retained feedback. Separately verify phone authentication, shared-device refresh, UAT backup restore, hosting, and release promotion. Do not describe local/API-verified work as deployed, externally authenticated, checkout-capable, or production-ready.
